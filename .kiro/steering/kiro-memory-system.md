# Kiro 持久记忆系统

跨会话持久记忆系统，灵感来自 claude-mem，适配 Kiro 原生能力（steering + hooks + markdown 文件）。

## 核心理念

每次会话中，Kiro 自动捕获有价值的观察（observations），压缩为结构化记录，存储在 `.kiro/memory/` 目录下。新会话开始时，通过 steering 自动注入最近的上下文，实现跨会话记忆延续。

## 记忆架构

```
.kiro/memory/
├── observations/          ← 观察记录（按日期分文件）
│   ├── 2026-03-12.md
│   └── ...
├── summaries/             ← 会话摘要
│   └── latest.md          ← 最近一次会话摘要
├── timeline.md            ← 最近活动时间线（自动生成，限制条目数）
└── index.md               ← 记忆索引（按类型/概念分类）
```

## 观察类型

| 类型 | 图标 | 说明 |
|------|------|------|
| `discovery` | 🔵 | 代码结构、API 行为、项目模式的发现 |
| `bugfix` | 🔴 | Bug 修复：根因 + 解决方案 |
| `feature` | 🟣 | 功能实现：新增/修改的功能 |
| `decision` | ⚖️ | 架构/设计决策及其理由 |
| `change` | ✅ | 代码变更记录 |
| `refactor` | 🔄 | 重构操作 |

## 观察记录格式

每条观察记录使用以下格式：

```markdown
### [OBS-XXXX] 🔵 标题

- **时间**: YYYY-MM-DD HH:mm
- **类型**: discovery | bugfix | feature | decision | change | refactor
- **文件**: 相关文件路径（逗号分隔）
- **概念**: 相关概念标签（逗号分隔）

**摘要**: 一句话描述发生了什么

**详情**: （可选）更详细的上下文、代码片段、解决方案

---
```

## 会话摘要格式

每次会话结束时生成摘要，保存到 `summaries/latest.md`：

```markdown
# 会话摘要

- **日期**: YYYY-MM-DD
- **项目**: 项目名称

## 用户请求
用户本次会话的主要目标

## 调查发现
调查过程中发现的关键信息

## 学到的知识
本次会话中获得的新认知

## 完成的工作
实际完成了什么

## 后续步骤
建议的下一步操作
```

## 时间线格式

`timeline.md` 保持最近 30 条观察的紧凑索引：

```markdown
# 最近活动

| ID | 时间 | 类型 | 标题 | 文件 |
|----|------|------|------|------|
| OBS-0042 | 03-12 15:30 | 🔵 | 发现 ScrollView 回收机制 | UIXxxView.lua |
| OBS-0041 | 03-12 14:20 | 🔴 | 修复 Toggle 回调循环 | UIYyyPanel.lua |
```

## 操作规则

### 何时记录观察

完成一个有意义的操作后，评估是否值得记录：
- 修复了一个 Bug？→ 记录 `bugfix`
- 发现了代码结构或 API 行为？→ 记录 `discovery`
- 实现了新功能？→ 记录 `feature`
- 做了架构/设计决策？→ 记录 `decision`
- 进行了代码变更？→ 记录 `change`（仅记录重要变更）
- 重构了代码？→ 记录 `refactor`

### 何时不记录

- 简单的格式调整、拼写修正
- 用户只是问了一个问题，没有实际操作
- 重复的、已经记录过的内容

### ID 生成规则

- 格式：`OBS-XXXX`，四位数字，从 0001 开始递增
- 读取当天的观察文件，找到最大 ID，+1
- 如果是当天第一条，从 `index.md` 中找全局最大 ID，+1

### 记录流程

1. 确定观察类型和内容
2. 生成 ID
3. 追加到 `.kiro/memory/observations/YYYY-MM-DD.md`
4. 更新 `.kiro/memory/timeline.md`（保持最近 30 条）
5. 更新 `.kiro/memory/index.md`（按类型分类索引）

### 会话结束时

生成会话摘要，覆盖写入 `.kiro/memory/summaries/latest.md`。

## 上下文注入

新会话开始时，Kiro 通过本 steering 文件自动获知记忆系统的存在。当需要回顾历史时：
- 先查看 `timeline.md` 获取最近活动概览
- 再根据需要查看具体日期的观察文件
- 查看 `summaries/latest.md` 了解上次会话的上下文

## 与自我学习系统的关系

- **记忆系统**（本系统）：记录"做了什么"——观察、发现、变更的事实记录
- **学习系统**（self-improving-agent）：记录"学到了什么"——错误教训、纠正、最佳实践
- 两者互补：记忆系统提供历史上下文，学习系统提供经验教训
- 当一个观察同时也是一个教训时，两边都记录

## 隐私控制

如果用户在消息中使用 `<private>内容</private>` 标签包裹的内容，不记录到记忆系统中。
